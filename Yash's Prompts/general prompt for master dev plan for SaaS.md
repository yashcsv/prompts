# PROMPT INFRASTRUCTURE REQUIREMENT

For each AI-eligible task, define a prompt registry entry.

Do not write prompt bodies.

Only write descriptor metadata.

For each prompt define:

### Prompt Name
Short and specific.

### About
What the prompt is for.

### Purpose
What outcome it is meant to achieve.

### Scope
What part of the workflow it applies to.

### Use
When it is used and in what situation.

### Input
What documents, data, context, or files it requires.

### Output
What kind of result it should produce.

### Dependencies
What must already exist.

### Ownership
Who approves or owns it.

### Automation Level
Autonomous / hybrid / human-controlled.

### Risk Level
Low / medium / high / critical.

### Validation Rules
How the output is checked.

### Review Rules
Who reviews it before execution.

### Failure Modes
What can go wrong.

### Completion Criteria
What counts as done.

This is mandatory.

# AI / HUMAN / QA BOUNDARY RULES

Classify work into three zones:

## 1. AI-AUTONOMOUS
Work AI can safely perform with validation.

Examples:
- boilerplate generation
- draft scaffolding
- test drafting
- docs drafting
- repetitive implementation support

## 2. HYBRID
Work AI can assist with, but humans must review.

Examples:
- architecture decisions
- workflow design
- data modeling
- API shape review
- release planning
- quality review

## 3. HUMAN-CRITICAL
Work that must never be fully automated.

Examples:
- security approvals
- release approvals
- production environment changes
- billing/payment logic approval
- irreversible migrations
- business-critical decisions
- legal/compliance decisions
- role/permission changes

You must explicitly define where each workflow sits.
